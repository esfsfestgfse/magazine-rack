# Magazine Rack full application audit — 2026-09-24

## Scope

- Live GitHub Pages root: `https://esfsfestgfse.github.io/magazine-rack/index.html`
- Local source, Pages workflow, Worker source, release checks, shelf loader, service worker, and reader.
- Real Chrome DOM verification after the `6f889f0` deployment.

## Executive result

The app is visually available and the primary racks render, but this is not a clean stable release. The most important issue is that the deployed root is still the standalone monolith while a separate modular frontend exists in `apps/web/src/`; the Pages workflow explicitly rejects shipping the modular entrypoint. That gives us two architectures and makes fixes easy to apply to the wrong app.

The live page rendered 52 shelves and 1,127 visible cards during the audit. The first 35 shelves mostly populated. Thirteen shelves ended in an empty state, including Adult Mags and Adult Comics. Eight lower specialty racks were empty with fallback health after the serialized loader completed. This reproduces the exact class of “works at the top, empty below” failure that has appeared repeatedly.

## Architecture findings

### P0 — Two frontends, one shipped

- `apps/web/index.html` is a roughly 6,000-line standalone application and is what Pages deploys.
- `apps/web/src/main.js`, `styles.css`, `live-sources.js`, `shelf-catalog.js`, `api.js`, and `store.js` form a separate modular frontend.
- `.github/workflows/pages.yml` copies `apps/web/index.html` directly and rejects a module entrypoint with the message that the standalone file must remain canonical.
- `pnpm run check` validates both trees, but it does not prove behavior parity between them.

**Impact:** fixes, QA, and source-query changes can land in the non-shipped architecture without affecting users.

### P1 — Loader can finish silently empty

- The standalone loader retries pages whose records are filtered out as unreadable or irrelevant.
- After the skip budget is exhausted it converts the rack to an empty state, even when the provider reported a large catalog total.
- The live lower shelves demonstrate this path: no cards, no useful error, fallback health, and in several cases no count.

**Impact:** provider outages, query drift, and over-aggressive relevance filters look identical to “there are no items.”

### P1 — Health state is not a trustworthy contract

- `fallback` appears on many populated IA-backed shelves and on empty shelves.
- Provider totals are shown independently of the usable/readable card count.
- The frontend and the `scripts/audit-live-shelves.mjs` script do not audit the same runtime: the script imports modular adapters, while Pages ships the standalone app.

**Impact:** release checks can pass while the deployed UI is empty or degraded.

### P1 — Audit script is not a deployed smoke test

- `pnpm run audit:shelves` completed, but its output showed zero samples for most shelves and source fetch failures for Open Library/Europeana/XKCD.
- It reports `failedShelfCount: 5`, yet it does not load the GitHub Pages DOM or verify the deployed Worker contract.

**Impact:** it is useful as an adapter probe, not as the requested live release audit.

### P2 — Service-worker versioning is split

- The standalone HTML registers `sw.js?v=12` while `sw.js` uses shell cache `magazine-rack-shell-v17`.
- The modular source registers `sw.js?v=13`.

**Impact:** cache invalidation is harder to reason about and stale behavior can differ by entrypoint.

### P2 — Production security/release evidence remains incomplete

- Existing security documentation still identifies production-origin/D1 and shared-rate-limit concerns.
- The Worker has good unit-level guards, but this audit could not complete live Worker health/diagnostics requests from the shell because external socket access is blocked in the current runtime.
- Chrome DevTools MCP was not connected, so LCP/INP/CLS/TBT are not measured in this report.

## Priority repair sequence

1. Make one frontend canonical. Either ship the modular frontend and remove the monolith, or move the loader/catalog logic into tested modules while keeping the standalone entrypoint. Do not maintain both behaviorally.
2. Add a real deployed smoke test that loads the Pages URL, waits for the background pump, records every shelf’s card count/status/cover/readability/access state, opens one issue per source, and fails on empty or silently stuck shelves.
3. Replace silent empty completion with a typed state: `live`, `stale`, `degraded`, `unavailable`, `filtered-empty`, or `catalog-only`. Preserve provider totals but never present them as usable content counts.
4. Repair the serialized loader so every shelf reaches a terminal state with an explicit reason, and ensure lower shelves cannot be skipped after a prior shelf failure.
5. Repair the specialty queries and source adapters for Music, Hot Rod, Trains, Aviation, Photography, Humor, SF Fanzines, Board Games, Folkscanomy, IA Strips, and Adult shelves. Remove a rack only after its source is proven catalog-only or unreadable.
6. Make the audit script target the deployed runtime, with a separate adapter-contract test for modular source code.
7. Add real mobile/reader QA at 390px and 430px widths, including source fallback, fullscreen, page controls, close/reopen, and next/previous issue behavior.
8. Add measured performance tooling after Chrome DevTools MCP is connected, then tag a release only when the live smoke test and shelf gates pass.

## Release decision

**Not ready for a stable release.** The app is not catastrophically down, but the empty lower shelves, empty Adult racks, split frontend architecture, and non-deployed audit script are release-blocking quality issues.
